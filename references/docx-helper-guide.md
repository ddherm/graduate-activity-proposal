# DOCX 定点填表与原路径更新

本工具读取、回填明确的Word字段，不生成申报内容，不判断材料是否可提交。先按参考材料确定各角色的格式，再精确填文字；helper不会自动套用外部参考文档的字体或版式。

## 两阶段使用

需要Python 3、`python-docx`与`lxml`，可由代理在当前环境安装 [依赖列表](../requirements.txt)。

以下路径和哈希仅示意，应替换为本次真实值；`work/`为内部工作区。

```sh
python3 scripts/docx_helper.py inspect '官方附件.docx' > 'work/inspect.json'
python3 scripts/docx_helper.py patch '官方附件.docx' 'work/patch.json' 'work/候选.docx'
python3 scripts/docx_helper.py check 'work/候选.docx'
```

随后由代理渲染候选DOCX、逐页查看，并核对正文、预算、跨附件数字及参考格式。**检查通过后**，记录该候选的SHA-256，再原位回写：

```sh
python3 scripts/docx_helper.py commit '官方附件.docx' 'work/候选.docx' \
  --source-sha256 '源文件原始SHA-256' \
  --candidate-sha256 '已渲染检查候选的SHA-256' \
  --backup-dir 'work/internal-backups'
```

`patch`只创建内部候选，拒绝输入输出相同及覆盖已有候选。`commit`按指定原路径更新，保留文件名和位置；另存副本不是原位填写的替代交付。用户已要求原位修改时，代理连续完成上述工作，不为备份或回写重复询问。仅优化skill或做教学测试时，不调用commit更新真实用户附件。

候选内容、字体或分页发生改动后必须重新渲染检查，不能更新哈希后沿用旧版核验。工具本身不验证排版审阅是否完成，返回的`layout_review_verified_by_tool`始终为`false`。

## 定位、格式与补丁

`inspect`给出源文件SHA-256、正文段落、表格、去重单元格及run。坐标从0开始；合并格只使用canonical ID，`aliases`用于识别覆盖范围。段落含`ppr_xml`和`run_ids`，run含`rpr_xml`；XML仅反映直接格式，未写出的属性可能从样式继承，不能将空值当作格式已正确。

补丁继续使用`schema_version: 1`，原有段落/单元格操作兼容。每条操作须精确匹配`expect`，来源哈希失配时重新读取当前文件，不能只改哈希强行运行。

```json
{
  "schema_version": 1,
  "source_sha256": "使用inspect返回的真实值",
  "operations": [
    {"target": "body.p1", "expect": "原有单一格式文字", "text": "本次正文"},
    {"target": "body.t0.r1.c1.p0.run1", "expect": "原占位文字", "text": "本次填写内容"}
  ]
}
```

- **整段替换**：有文字的run须具有一致的直接格式；混合字号、加粗、颜色、字体等情况下，工具拒绝将全文塞入首run。单一格式段落使用第一个有文字run；空字段依原run或段落样式继承，仍需核对其是否符合正文角色。
- **精确run替换**：使用实际inspect给出的`.runN`，保留该run属性和其他run。适用于“固定标签＋不同格式填写区”等结构。占位文字跨多个run时逐一精确处理，或使用文档编辑器；不猜测任意字符串的格式分配。
- 同一run重复操作，或整段/整格操作与其下run重叠时拒绝；同段中不同run可以分别修改。run操作也受签批区保护。
- 多段落单元格使用各段ID，或`paragraphs`数组且长度与现有段数相同。文字中的`\n`是段内换行，不新建段落。插入/克隆段落、表格增行、套用外部参考格式、目录刷新仍由文档编辑流程负责。

[template-patch.json](../examples/template-patch.json)是配套附件1快照的匿名教学样例，使用10条精确run操作填两个字段，已于2026年10月4日实测通过。它保留原run格式，不自动修正原模板提示色或套用参考格式；只能演示文字定位与格式保留，不能把局部测试输出当作申报材料。实际源文件或run格式变化后，重新inspect再使用。

## 保留边界与提交行为

`patch`基于一次源文件字节快照读取正文及ZIP，避免把两个时点的内容拼进候选；生成候选前再检查源哈希。只改变`word/document.xml`，其他包成员内容逐字节保留，包括样式、图片、关系、元数据及页眉页脚。压缩后的整个文件不保证字节相同。

原行列、合并、段落/单元格/表格/节属性保持。含图片、字段、超链接、修订、批注引用或分页符的复杂段落转交文档编辑器；嵌套表格不能整格替换。inspect不提供页眉页脚或文本框的填表坐标。签名、盖章及审批意见仍由对应人员办理。

`commit`执行以下步骤：

1. 校验源文件与候选的指定哈希，检查DOCX包完整性和CRC；拒绝源文件符号链接及源候选同路径。
2. 在指定内部备份目录创建唯一备份，并复核备份哈希。
3. 将已核验候选写到源目录的唯一临时文件，保留源文件权限位；再次核对临时文件、源文件和候选哈希。
4. 在同一文件系统内原子替换原路径，再检查更新后的哈希。源文件位于外盘时，仍采用源目录临时文件，避免跨盘直接替换失败。

替换前的哈希冲突、无效候选或写入失败不会覆盖源文件；临时文件会清理。若替换已完成而后验读取失败，工具明确报告这一状态并保留原始备份，不声称“源文件未改”。候选与内部备份不放入提交材料包。该机制减少并发覆盖风险，不替代应用间文件锁；发现源文件期间已变动应重新读取，不覆盖较新版本。

`check`查找XX、202X、填表提示和待补充等痕迹，只输出复核线索。用户要求保留的图位、联系人空白与真实签批栏需按约定处理；没有命中不代表资料齐全。最终仍需核对真实性、规则、预算、未填项及逐页版式。
