# 格式基准与原位保存

## 权威来源与适用范围

本规则落实用户2026年10月4日明确要求：格式以指定三份成稿为基础，实际填写直接修改官方附件原文件；同日后续明确提出的局部间距要求优先于样本。下列表格列出当前操作规格，标注“用户覆盖”的值来自最新指令，其余来自Word结构实测；均不是通知明文规定。只借用样本格式，不把项目事实、联系人、数量、预算或日期当作其他项目默认值。有使用者自己的参考件时先打开核对；没有时使用本文件及JSON中的包内规格。源样本未公开，其散列仅用于版本追溯，不是新用户必须取得的文件。字体名称按OOXML原拼写保留。机器可读的代表角色与继承记录见 [format-baseline.json](format-baseline.json)，按附件代号与role查询，不必全文加载。JSON的 `documents`（包括其 `effective_paragraph`）保留来源版本的历史实测与原 `source_sha256`，不表示参考件已按新指令改动；实际使用的最终有效格式必须叠加 `user_overrides`，不能直接将历史 `effective_paragraph` 当作当前操作规格。

本包提供三种附件的格式元数据，不公开已填项目成稿。A2对应特色活动申报表，A3对应申报书，A4对应策划书。个人参考件可选；本文件和JSON足以查阅默认字号、行距和角色差异。

位置记法：`p[n]` 是 `word/document.xml/w:document/w:body/w:p[n]`（只数 body 的直接子段落）；`Tn/Rn/Cn/Pn` 是 body 第 n 个直接子表格／该表第 n 行／该行 XML 第 n 个单元格／单元格第 n 段。合并格必须按 XML 单元格数定位，不能直接拿屏幕上的列序号代替。A3 的 T1 是封面留存的空布局表，正式申报表为 T2。页码以结构定位为主，不硬编码本次渲染页数。

## 最新用户覆盖：仅指定间距

覆盖优先级为：使用者本次最新明确格式要求 → 使用者本次指定参考件 → 本节已记录的包内覆盖 → 包内历史实测。本节覆盖是公开包默认值；当次参考件有不同要求时，不以作者的历史偏好覆盖使用者选择。未命中的角色与属性仍按原样本继承，不修改全局 Normal 或共享样式来实现局部要求。同一项目后续重读参考件，也不能用旧间距撤销使用者已明确提出的最新修改。

## 每次填写的格式操作

1. 读取当前写入文件、可选的用户参考件及包内 `user_overrides`。没有参考件时从包内对应角色元数据解析。分别选封面、各级标题、正文、表头、数据格、论证、图注和签批区的参考位置；解析样本继承后，仅叠加匹配角色的指定覆盖，得到本次最终有效格式。以下索引用于查找已记录版本，不能跳过原文核对后直接套在用户后来修改的文件上。
2. 将对应角色的段落/文字/单元格/表格/节属性用于目标位置。复制样式ID时必须核对其在目标文档的定义与继承链；同名Normal或同一styleId不保证同样格式。需要时同步必要样式定义，或精确写入该角色的有效属性，避免全局修改Normal误伤其他角色。
3. 局部内容修改按run或占位片段替换，保留标签、正文、数字、中点等不同格式。新增段落从同类正文继承；新增行从数据行继承，不克隆表头当正文。不要把上述段落定位、字号、图尺寸当整份文档的唯一值。
4. 保留空段、分节、封面及签批留白、图位、制表位、边框和合并。新图片按原位置与宽度适配并保持比例。内容过长用合理分页处理，不自行压缩字体/行距或把所有表格变成等宽列。
5. 内部工作区留存备份和候选，逐项比较候选的实际格式与叠加用户覆盖后的角色规格；渲染全部候选页面，对照参考页检查。渲染器缺字体时保留成稿字体声明，替代字体预览只验证其能显示的布局，不声称字形完全相同。样本页数和已存在的分页现象不作为固定验收页数。
6. 核验后回写实际附件原路径。可用 [docx_helper的patch/commit流程](docx-helper-guide.md)，也可用文档编辑工具原位保存。回写前核对当前源文件未被用户更新，写后重新打开检查。备份、候选及核验PDF留在内部工作区；不另交付相同内容的Word套件或ZIP，不重复询问已明确授权的覆盖操作。

## 正确解析继承

三份文件的默认段落样式都是 `styleId="a"`、名称 `Normal`，其实际属性是：中文 `方正仿宋_GBK`；ascii/hAnsi `Times New Roman`；字号 `w:sz=28` 即 14 pt；`szCs=24` 是复杂文字字号，不能据此把中文判成 12 pt。Normal 段落两端对齐，`widowControl=0`。`docDefaults` 的字体是主题字体，随后被 Normal 和直接格式覆盖。

解析顺序为 docDefaults → 表格样式继承 → 段落样式 basedOn 链 → 字符样式 → run 直接格式。每种字体槽位分别追踪来源，后层明确的字体声明覆盖前层；run 未写 `rFonts/eastAsia` 或 `sz` 仍可能完整继承 Normal。A4 正文 p51、流程表 T1/R2/C2/P1 就是典型：run 只写复杂文字字体或颜色，中文实际上仍为方正仿宋_GBK 14 pt。不要把 `pPr/rPr`（段落标记的格式）当作正文 run 的最终格式；A4 p4 的段落标记写仿宋，实际标题 run 写方正大标宋简体。

`w:bCs` 仅表示复杂文字加粗，不能把它当作中文/拉丁文 `w:b`。本样本一、二级标题多数没有 `w:b`；字体自身笔画较粗不等于另加粗。三级标题有 `w:b`。

单位：`sz` 为半磅；twip 为 1/20 pt；`firstLineChars/leftChars/hangingChars` 为 1/100 字符；`beforeLines/afterLines` 为 1/100 行；边框 `sz` 为 1/8 pt。`lineRule=exact` 才把 `line/20` 读作固定磅值。未设置的段前后不是“缺失错误”；本样本 Normal/docDefaults 没有段前后设置，普通正文有效段前后为 0。保留某个角色原有的字符单位、固定单位及局部留白，不做全文统一覆盖。

## 页式、页眉与页脚

- 全部 A4 纵向：`pgSz w=11906 h=16838` twips，约 21 × 29.70 cm；单栏，gutter=0。
- A2 唯一节：上/下 `1440`（2.54 cm），左/右 `1800`（3.175 cm）；页眉距顶 `851`（约1.50 cm），页脚距底 `992`（约1.75 cm）；`docGrid type=lines linePitch=312`（15.6 pt）。
- A3 前3节：上/下 `1701`（约3 cm），左/右 `1417`（约2.5 cm）。第1节页眉/页脚距离都是720（1.27 cm）；第2、3节分别851/992。第4节正式表格区采用 A2 的1440/1800边距。节结束位置为 p23、p25、p40，最后是 body 末尾 sectPr；第3节是 continuous，其余未声明时按 nextPage。
- A4 前3节同 A3 前3节边距，页眉/页脚距离均851/992；第4节正文区为1440/1800。节结束位置 p22、p24、p43（目录末项）；第3节 continuous。
- 有效页眉按关系保留，不能全文件重新建立同一种页眉。A2 header1、A3 header1、A4 header1有校研会徽标和“真诚服务／共同进步”，文字华文中宋12 pt、居中；段底0.5 pt单实线，`space=1`；保留原图片关系。A3封面第一节未引用该页眉；A4第二节切换到空文字但有底线的 header2，后续继承该页眉。A3 header1还有第二个空段落及底线，不能一概删除。
- A2 footer1为空，无可见页码。A3/A4 footer1居中，固定14 pt行距，`snapToGrid=0`，用真正 PAGE 域；可见页码及两侧“—”run均10 pt，数字 Times New Roman、短横两侧 run 中文方正仿宋GBK。域代码 run继承14 pt并不表示可见页码14 pt。不要把缓存的“1”复制成所有页的固定页码。
