# 资料采集与事实边界

## 最小澄清

先处理会改变模板或资格的未知项，再补正文事实。层级和校级具体项目必须明确；用户仅要求本skill的制作/修改时无需澄清真实活动。

一次收集最关键缺项的问法：

> 请补充牵头及参与学院（含校区）、负责人和联系方式、拟办时间地点、预算及已有资源。校级活动还需提供本学院本轮全部牵头/参与项目，便于填写附件1。未定的资源可以直接标“拟联系”，已有文件我会自行提取。

只问缺失项。若现有对话已清楚说明院级B类雷达工作坊，别再让用户选一次校/院级。用户只要求润色一段已确定用途的文字时，无需启动整套文件制作。

## 单一信息底稿

建议保存在工作区，可用表或结构化文件；不要要求用户自己填技术格式。

| 字段组 | 最小内容 | 来源/状态 |
|---|---|---|
| 申报定位 | 学年、校级/特色、项目编号及官方名称/自拟活动全称；特色活动的竞标档位（如A级命题）与内容类别（四类之一）分开记录 | 通知+用户选择；“命题/全类型”不是四类内容类别 |
| 团队 | 牵头、参与单位全称、分别所在校区、实际覆盖校区、责任角色 | 用户确认；不得只从学院名称猜校区 |
| 联系 | 负责人/联络人姓名及电话，申报日期 | 用户提供；姓名与电话不足不可造填 |
| 校级全量台账 | 本院本轮牵头清单、参与清单、是否含当前项目、排除不计项目 | 去重后分别计数，不能默认“其他项目=0” |
| 基础 | 学生需求证据、调研范围/样本/时间、上一届活动与可证成果 | 原材料位置；历史数据标年份 |
| 内容 | 拟定流程、对象、场次、容量、报名筛选、服务动作、负责人 | 区分已定方案与可调建议 |
| 时间空间 | 举办日期、筹备复盘、场地申请进度、跨校区交通或远程服务 | 未确认场地不写已获批 |
| 资源 | 嘉宾/企业/老师/校友、已确认/已接洽/拟联系、证明材料 | 资源名、承诺范围和证据对应 |
| 经费 | 项目总额、申请资助、确认的学院现金支持、拟赞助、已有/借用实物 | 估价依据；不把未落实现金做已落实 |
| 成效 | 目标、人数或人次、测量方法、验收时间、责任人、证据 | 明确目标不是历史实绩 |

不要抄原通知联系人、历史负责人或同名学院往年资源补本次空白。

联合承办总数按不同学院研究生会计算，包含牵头单位，不把主办方校研究生会或同一学院的不同部门另算一所。学院实际跨校区时分别记录真实覆盖与本项目名额归属；通知没有说明的重复归属问题须核对口径，不能把同一学院自动算作两所。

## 事实与计划的写法

| 状态 | 可用表达 | 不可偷换为 |
|---|---|---|
| 真实调研 | “9月面向……回收有效问卷……，其中……（来源）” | 无问卷却写“调研显示68%” |
| 尚无调研 | “拟在报名阶段收集求职问题，并据此确定交流议题” | “同学普遍强烈要求……” |
| 意向资源 | “已与……初步沟通，具体出席安排待确认” | “邀请……担任嘉宾”且隐去待确认 |
| 尚未联系 | “拟联系具备……经验的校友；未落实时……” | “联合某企业共同举办” |
| 预期结果 | “计划完成……；活动后用……记录” | “已帮助……获得实习” |
| 学院既往案例 | “2025年曾……，本届资源需重新确认” | 直接写成2026年成果或本人经历 |

## 何时可以交付

- **成稿**：正文及可填写事实完整，年度/模板问题明确处理；真实签批保留；文档渲染核验完成。说明“待中标后打印签字”等实际后续动作。
- **待补信息稿**：身份、关键资源、资格、年度规范或数量台账缺失；明确待补清单和哪些文件受影响，不以“已完成全部材料”结项。
- **示例**：整个案例与数字均标“教学虚构/拟定”，不与真实申请混放，不生成假章假签。

不强制为了成稿完成尚未开展的调查；没有调查实证时可以据实呈现设计前提和需求征集计划。外部结果如录用、企业回复、媒体转载只能写合作意向或跟踪指标，不承诺自己无权控制的结果。
